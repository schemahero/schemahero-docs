## Basic Index

```yaml
indexes:
  - columns: [email]
    name: idx_users_email
```

## Unique Index

```yaml
indexes:
  - columns: [email]
    name: idx_users_email_unique
    isUnique: true
```

## Multi-Column Index

```yaml
indexes:
  - columns: [tenant_id, created_at]
    name: idx_users_tenant_created
```

Column order matters for query optimization.

## Index Types

<Tabs items={['PostgreSQL', 'MySQL']}>
  <Tab>
    ### B-tree (default)
    Best for equality and range queries:
    ```yaml
    indexes:
      - columns: [created_at]
        name: idx_created
        type: btree
    ```

    ### Hash
    For equality-only queries:
    ```yaml
    indexes:
      - columns: [session_id]
        name: idx_session_hash
        type: hash
    ```

    ### GIN
    For full-text search, arrays, JSONB:
    ```yaml
    indexes:
      - columns: [tags]
        name: idx_tags_gin
        type: gin
    ```

    ### GiST
    For geometric data, full-text search:
    ```yaml
    indexes:
      - columns: [location]
        name: idx_location_gist
        type: gist
    ```
  </Tab>
  <Tab>
    ### B-tree (default)
    Standard index type:
    ```yaml
    indexes:
      - columns: [email]
        name: idx_email
        type: btree
    ```

    ### Fulltext
    For text search:
    ```yaml
    indexes:
      - columns: [title, body]
        name: idx_content_fulltext
        type: fulltext
    ```
  </Tab>
</Tabs>

## Examples

<Tabs items={['PostgreSQL', 'MySQL', 'SQLite']}>
  <Tab>
    ```yaml
    schema:
      postgres:
        primaryKey: [id]
        columns:
          - name: id
            type: serial
          - name: email
            type: varchar(255)
          - name: tags
            type: text[]
          - name: data
            type: jsonb
          - name: created_at
            type: timestamp
        indexes:
          - columns: [email]
            name: idx_users_email
            isUnique: true
          - columns: [created_at]
            name: idx_users_created
          - columns: [tags]
            name: idx_users_tags
            type: gin
          - columns: [data]
            name: idx_users_data
            type: gin
    ```
  </Tab>
  <Tab>

      mysql:
        primaryKey: [id]

          - name: id

## Cassandra

Cassandra doesn't use traditional indexes in the schema definition. Indexes are implicit from the primary key structure:

```yaml
schema:
  cassandra:
    primaryKey:
      - [tenant_id]         # Partition key - equality queries
      - [created_at]        # Clustering key - range queries
    columns:
      - name: tenant_id
        type: uuid
      - name: created_at
        type: timestamp
      - name: data
        type: text
```

For secondary indexes in Cassandra, use CQL directly outside SchemaHero.
