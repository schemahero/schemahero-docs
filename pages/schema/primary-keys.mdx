# Primary Keys

Primary keys uniquely identify each row. The syntax varies by database.

## Basic Syntax

<Tabs items={['PostgreSQL', 'MySQL', 'SQLite', 'Cassandra']}>
  <Tab>
    ```yaml
    schema:
      postgres:
        primaryKey: [id]
        columns:
          - name: id
            type: serial
    ```
  </Tab>
  <Tab>
    ```yaml
    schema:
      mysql:
        primaryKey: [id]
        columns:
          - name: id
            type: int
            attributes:
              autoIncrement: true
    ```
  </Tab>
  <Tab>
    ```yaml
    schema:
      sqlite:
        primaryKey: [id]
        columns:
          - name: id
            type: integer
            attributes:
              autoIncrement: true
    ```
  </Tab>
  <Tab>
    ```yaml
    schema:
      cassandra:
        primaryKey:
          - [partition_key]      # Partition key(s)
          - [clustering_col]     # Clustering column(s)
        columns:
          - name: partition_key
            type: uuid
          - name: clustering_col
            type: timestamp
    ```
    
    Cassandra uses a nested array: first element is partition key(s), second is clustering column(s).
  </Tab>
</Tabs>

## Auto-Increment IDs

<Tabs items={['PostgreSQL', 'MySQL', 'SQLite']}>
  <Tab>
    Use `serial` or `bigserial`:
    ```yaml
    primaryKey: [id]
    columns:
      - name: id
        type: serial          # 4-byte auto-increment
      
      # Or for large tables:
      - name: id
        type: bigserial       # 8-byte auto-increment
    ```
  </Tab>
  <Tab>
    Use `autoIncrement` attribute:
    ```yaml
    primaryKey: [id]
    columns:
      - name: id
        type: int
        attributes:
          autoIncrement: true
      
      # Or bigint for large tables:
      - name: id
        type: bigint
        attributes:
          autoIncrement: true
    ```
  </Tab>
  <Tab>
    Use `integer` with `autoIncrement`:
    ```yaml
    primaryKey: [id]
    columns:
      - name: id
        type: integer
        attributes:
          autoIncrement: true
    ```
    
    **Note:** SQLite AUTOINCREMENT only works with INTEGER PRIMARY KEY.
  </Tab>
</Tabs>

## UUID Primary Keys

<Tabs items={['PostgreSQL', 'MySQL', 'SQLite']}>
  <Tab>
    ```yaml
    primaryKey: [id]
    columns:
      - name: id
        type: uuid
        default: gen_random_uuid()
    ```
  </Tab>
  <Tab>

    columns:
      - name: id
        type: char(36)
        default: "(uuid())"
    ```
  </Tab>
  <Tab>

    primaryKey: [id]
    columns:
      - name: id
        type: text
        # Generate UUID in application
    ```

## Composite Primary Keys

Multiple columns:

<Tabs items={['PostgreSQL/MySQL/SQLite', 'Cassandra']}>
  <Tab>
    ```yaml
    primaryKey: [tenant_id, user_id]
    columns:
      - name: tenant_id
        type: uuid
      - name: user_id
        type: uuid
      - name: role
        type: varchar(20)
    ```
  </Tab>
  <Tab>
    ```yaml
    primaryKey:
      - [tenant_id]            # Partition key
      - [user_id, created_at]  # Clustering columns
    clusteringOrder:
      column: created_at
      isDescending: true
    columns:
      - name: tenant_id
        type: uuid
      - name: user_id
        type: uuid
      - name: created_at
        type: timestamp
    ```
  </Tab>
</Tabs>

### Common Patterns

**Multi-tenant tables:**
```yaml
primaryKey: [tenant_id, id]
columns:
  - name: tenant_id
    type: uuid
  - name: id
    type: serial
```

**Many-to-many join table:**
```yaml
primaryKey: [user_id, role_id]
columns:
  - name: user_id
    type: integer
  - name: role_id
    type: integer
foreignKeys:
  - columns: [user_id]
    references:
      table: users
      columns: [id]
  - columns: [role_id]
    references:
      table: roles
      columns: [id]
```

## UUID vs Integer

| | UUID | Integer |
|-|------|---------|
| **Size** | 16 bytes | 4-8 bytes |
| **Generation** | Anywhere | Database only |
| **Security** | Non-guessable | Sequential |
| **Performance** | Slightly slower | Faster |
| **Distributed** | No coordination | Needs sequences |

**Use UUID when:**
- IDs generated outside database
- Distributed systems
- IDs in URLs should be non-guessable

**Use Integer when:**
- Single database
- Performance critical
- IDs are internal only

## Cassandra Primary Keys

Cassandra primary keys have special semantics:

```yaml
schema:
  cassandra:
    primaryKey:
      - [tenant_id]              # Partition key
      - [created_at, user_id]    # Clustering columns
    clusteringOrder:
      column: created_at
      isDescending: true
```

- **Partition key** — Determines data distribution. Queries must include it.
- **Clustering columns** — Sort order within partition. Range queries allowed.
- **Clustering order** — ASC (default) or DESC per column.

Query patterns:
```sql
-- ✓ Allowed: full partition key
SELECT * FROM users WHERE tenant_id = ?;

-- ✓ Allowed: partition + clustering prefix
SELECT * FROM users WHERE tenant_id = ? AND created_at > ?;

-- ✗ Not allowed: missing partition key
SELECT * FROM users WHERE created_at > ?;
```
